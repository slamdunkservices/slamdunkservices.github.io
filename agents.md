# Agents Guide — Slam Dunk Bets Site

## What this is

Marketing + blog site for **Slam Dunk Bets**, an NBA, WNBA & MLB prop picks service — first baskets for basketball, home runs and NRFI/YRFI for baseball. Quarto website published to GitHub Pages at <https://slamdunk.bet> (custom domain set via the `CNAME` file).

## Tech

- **Quarto website** — see `_quarto.yml`. Theme: `litera` (Bootstrap 5-based) with `custom.scss` and `styles.css` overrides.
- **Content is plain markdown** — no R or Python code chunks in any `.qmd`, so rendering needs only Quarto itself. Build-time logic lives in one Lua filter (`_filters/seo-schema.lua`), which also needs only Quarto.
- **Quarto binary: 1.9 or newer is required** (`canonical-url`, `draft-mode`, `body-classes`, listing feeds). Installed at `~/.local/bin/quarto` (1.10.18, tarball install) and symlinked from `/usr/local/bin/quarto`, so `quarto` on `PATH` is the right one. An old root-owned 1.3.361 still sits in `/Applications/quarto`; never use it — it regresses Open Graph tags and every feature above. Check `quarto --version` before publishing.
- **Authoring:** RStudio with the visual editor (`slamdunkservices.github.io.Rproj`). Keep `PythonType: r-reticulate` set in the `.Rproj`.

## Commands

- `quarto preview` — live local preview with hot reload
- `quarto render` — build the site into `_site/` (gitignored)
- `_scripts/publish.sh` — the publish command: checks the Quarto version and a clean tree, runs `quarto publish gh-pages`, then pings IndexNow with the changed pages (see Publishing)

There are no tests or linters. The verification greps in the SEO section below are the closest thing.

## Publishing

Publishing uses the Quarto `publish` command, which renders locally and pushes the built `_site/` to the `gh-pages` branch. Full docs: <https://quarto.org/docs/publishing/github-pages.html>. Run it through `_scripts/publish.sh`, which refuses a dirty tree (the sitemap's `lastmod` values come from git history, so uncommitted edits would publish with a stale date), then diffs the new sitemap against the one that was live and submits every new or changed URL to IndexNow once the key file answers on the live site. `_scripts/indexnow.py --all` resubmits every page; `--dry-run` shows what would be sent.

No GitHub Actions workflow — all publishing happens from the author's machine. On first publish, Quarto writes a `_publish.yml` file recording the target; commit it when it appears.

Typical flow:

1. Edit on `main`
2. `quarto --version` — must be 1.9+
3. `quarto preview` — check locally
4. Commit + push `main`
5. `_scripts/publish.sh` from the repo root (must be on a branch that is **not** `gh-pages`)
6. After publish, spot-check `https://slamdunk.bet/robots.txt`, `/llms.txt`, `/sitemap.xml`, `/articles.xml`

## Common tasks

**Add a blog post.** Create `posts/YYYY-MM/slug.qmd` with this frontmatter (every key matters for search and social cards):

```yaml
---
title: "Post Title"
subtitle: "Optional kicker"
author: Slam Dunk Bets
date: YYYY-MM-DD
categories: [nba, first-basket, methodology]
draft: false
description: "One or two plain sentences, 120-220 characters, that say what the post covers. Becomes the meta description, the OG description, the listing blurb, and the JSON-LD description."
image: "/images/posts/slug-image.jpg"
image-alt: "What the image shows"
---
```

- **Category vocabulary** (use only these): `nba`, `wnba`, `mlb`, `first-basket`, `home-runs`, `methodology`, `roi-recap`, `strategy`.
- Every body image needs alt text: `![What it shows](/images/posts/foo.jpg)`.
- Put the topic in the `title` itself ("How Do We Predict Home Runs? Part 1: Pitch Data"), not in `subtitle`: the title is the `<title>`, the H1, the JSON-LD headline, and what search and AI answer engines cite.
- Break the body into `## ` sections every few paragraphs with headings that read as answers ("What counts as a playable edge"). Answer engines and featured snippets extract headed sections; a wall of paragraphs gets skipped.
- Link to at least one other page on the site (the FAQ, a series part, a recap) and, for a multi-part series, end every part with the shared `::: {.series-nav}` block listing all parts (styled in `styles.css`). Link forward to the next part in the closing paragraph.
- Name image files descriptively (`red-alert-light.jpg`, not `IMG_3068.jpg` or a Wikimedia filename with parentheses). Keep images at or under 1600px on the long edge and roughly 300 KB (`sips -Z 1600 -s formatOptions 45 in.jpg --out in.jpg` works; `sips` upscales smaller images with `-Z`, so skip the flag for anything already smaller). Oversized photos were the single biggest Core Web Vitals problem on the site.
- Link subscribe CTAs to `https://sharpduel.com/slam_dunk_bets` (preferred) and Whop only as `https://whop.com/slam-dunk-bets` (no `www`, no trailing slash).
- Add a bullet for the post under the matching section of `llms.txt`.
- When you later edit a published post in a way a reader would notice, set `date-modified: YYYY-MM-DD`; it feeds `dateModified`, `article:modified_time` and the visible "Modified" line. The sitemap `lastmod` comes from git automatically.
- The post appears automatically on `articles.qmd` and in `articles.xml`. `draft: true` keeps it off the listing but still renders an empty page; park truly unfinished posts in `_drafts/` instead.

**Rebuild the stats pages.** `stats/` is generated from the league data mirrors (roots in `~/.<league>_jobs.env`): NBA and WNBA from `02_curated/<l>_first_events` (earliest `fgm`/`points` row per game and per team; the `shot_type` is the method), `<l>_tip_events`, box scores (starters) and game logs (dates, home/away); MLB from `01_raw/linescores` (inning 1 runs), `schedules` (regular season, Final) and `probables` (listed starters). Run, then render the cards, then render the site:

```bash
/Users/jim/Code/jobs/mlb/.venv/bin/python _scripts/stats/build.py          # or: build.py nba
CARDS_TSV=_scripts/stats/cards.tsv _scripts/og-cards/build.sh              # one card per generated page
```

The "current" basketball season is the latest with 100+ games in the data, so early in a season the pages keep showing the previous one; MLB needs 200+ regular-season games. Rebuild about monthly in season and after each season ends, then publish. Team slugs come from the full team name (`los-angeles-lakers`); if a team is renamed the old page goes away, so add a redirect or keep the old file. Generated pages carry `date-modified` automatically.

**Add a guide.** Guides are plain pages in `guides/` with `title`, `pagetitle`, `description`, `date-modified`, `image`/`image-alt` (a card from `_scripts/og-cards/cards.tsv`), `## ` sections and `.faq-item` blocks. Add the page to the navbar "Guides" menu, the list on `guides/index.qmd`, and the Guides section of `llms.txt`. Keep book-rule claims hedged ("most books", "check the market rules"); grading differs by book.

**Monthly results post.** In season, publish one results post per month (NBA from November, WNBA from June, MLB from May). `python _scripts/roi-chart/month_stats.py YYYY-MM` prints the month's totals, season to date, results by market and book, top and bottom players and the largest wins for every league with wagers that month (NBA and WNBA from the ledgers, MLB per product from the daily ROI files). Copy `_drafts/monthly-results-template.qmd` to `posts/YYYY-MM/results-YYYY-MM.qmd`, fill it in, draw the season-to-date chart with `_scripts/roi-chart/season.R`, add a bullet to `llms.txt`. Report style, no plays. Use the `roi-recap` category so the recaps list together.

**Add or update a market page.** Market pages live under `nba/`, `wnba/`, `mlb/`, `nfl/`, `nhl/` (hub = `index.qmd`). Each has a lede, the markets, how we project them, a track record table by season (numbers from the ledgers; `_scripts/roi-chart/season_stats.py` and the per-market summary it prints are the source), a sample alert, `::: {.faq-item}` blocks (the filter emits FAQPage for them on any page), and the Sharpduel CTA. Add new pages to the navbar `menu` in `_quarto.yml` and to the "Picks by sport and market" section of `llms.txt`. The `stats/` and `guides/` folders get the same breadcrumbs (Home > Stats > page). Update the track-record tables after each season along with the FAQ. When the numbers change, also bump `date-modified` in the page frontmatter (it becomes `dateModified` in the JSON-LD and the "Modified" line under the title), update the "Updated <date>, from our graded ledgers" sentence under the table, and rebuild the page's share card.

**Run a paid campaign.** Point ads at `https://slamdunk.bet/free-trial.html` with UTM tags (`?utm_source=x&utm_medium=paid_social&utm_campaign=<name>`), which GA4 picks up on its own. For X conversion tracking, set `X_PIXEL_ID` and `X_CTA_EVENT_ID` at the top of `scripts/site-analytics.js` (from X Ads > Events Manager); every Sharpduel/Whop click then fires that event. Turning the pixel on means updating the "Advertising" section of `privacy.qmd`. X treats picks/tipster services as gambling content, so the ad account needs X's gambling authorization first.

**Edit a page.** Edit the `.qmd` at repo root, preview, commit, publish. Every root page has `title`, `pagetitle` (browser/search title; Quarto appends " – Slam Dunk Bets"), and `description` in its frontmatter. Keep them when editing; write them for any new page. Body sections on root pages use `## ` headings (the title is the H1; never skip to `### `). On `faq.qmd` the question in each `.faq-item` is a `## `; on sport pages, where the items sit under a `## ` section, it is a `### `.

**Change pricing.** Prices live in five places and must match: the table and `schema-offers` block in `subscribe.qmd`, the "How much does it cost?" answer in `faq.qmd`, the key-facts paragraph in `llms.txt`, and the table and fine print in `free-trial.qmd`.

**Update the ROI numbers.** The FAQ "What kind of ROI" answer, the `## Track record` line in `llms.txt`, and the headline claim ("8,000+ units", in `index.qmd`, `about.qmd`, `faq.qmd`, `_quarto.yml` description, `SITE_DESC` in `_filters/seo-schema.lua`, and `_og/og-default.html` → regenerate the PNG) all come from the graded ledgers, not from memory. Sources and method:

- NBA and WNBA season snapshots: `~/Code/adhoc/bet_tracking/<LEAGUE>/<season>/bet_tracking_consolidated.csv` (registry: `slam_dunk_tracking.R` there). Net = sum of `units_standardized_net`; ROI = net / sum of `units_standardized_bet` (voids excluded from the denominator). 2021-22 and 2022-23 are spreadsheets at flat stakes (`Win`/`Loss` outcomes, American `Odds`, `Units` staked); 2021-22 computes to +572 net on 3,349 staked (17.1%), which is what the FAQ and `llms.txt` show. By decision (2026-09-14) the site keeps 2022-23 at +1,610 with its Kelly footnote even though the spreadsheet computes to about +929.
- The homepage chart `images/home/cumulative_total.png` is built by `_scripts/roi-chart/build.sh` (Python reads the ledgers above, R draws the chart). It covers NBA, WNBA, and every MLB product (home runs, NRFI/YRFI, and the stolen bases, RBI, runs and total bases markets added in September 2026), and it prints every season's net and ROI as it runs. 2022-23 is scaled to the +1,610 basis so the line agrees with the headline; on the raw spreadsheet basis the all-time total is about 680 units lower. Rebuild it whenever the FAQ numbers change, and update the date in its caption in `index.qmd`. For a season recap post, `_scripts/roi-chart/season_stats.py nba|wnba` and `_scripts/roi-chart/mlb_season_stats.py [daily.csv]` print the season's tables (by game type, market, month, book, player, largest wins, projection accuracy), and `_scripts/roi-chart/season.R` draws the season chart with the playoffs shaded from a daily CSV (date, period, units_standardized_net; the MLB script writes it when given a path); the 2026-10 recaps were built this way. Last built 2026-10-30, through 2026-10-29: 8,565 units.
- Live WNBA season: `$WNBA_DATA_ROOT/02_curated/wnba_first_to_score/tracking/ledger/*.csv` (exchanges already excluded). The adhoc snapshot of the current season goes stale; prefer the ledger.
- MLB: `$MLB_DATA_ROOT/02_curated/bet_tracking/<product>/roi_daily.csv`; use only rows where `market == "ALL"` (per-market rows would double-count). Net = sum of `net_units_std`, staked = sum of `staked_units_std`. The `plays` column counts voided plays too; the site's play counts exclude voids, so take them from `alerted_plays/*.csv` (one row per wager; a play is a game, player and market) via `mlb_season_stats.py`. The `__with_exchanges` products are not used on the site.
- Read CSVs with `/Users/jim/Code/jobs/mlb/.venv/bin/python` (pandas); the two `.xlsx` seasons need `/Users/jim/Code/jobs/atp/.venv/bin/python` (openpyxl). Data roots are defined in `~/.<league>_jobs.env`; NBA has no local root (history is in the adhoc tree and `gs://sdbs_nba`).

## SEO and AI discoverability

What the build produces, and where each piece comes from:

- `<title>`, `<meta name="description">`, Open Graph and Twitter cards — from each page's `pagetitle`/`title`, `description`, `image`, `image-alt`, with site-wide fallbacks in `_quarto.yml` (`website.description`, `website.image`). Quarto builds these from YAML, so a description must be written in frontmatter; the Lua filter cannot backfill it.
- `<link rel="canonical">` — `canonical-url: true` plus `site-url`.
- `sitemap.xml` — automatic from `site-url`; drafts excluded; `lastmod` rewritten to git commit dates by the post-render hook.
- `robots.txt`, `llms.txt` — source files at repo root.
- `articles.xml` — the `feed:` block on `articles.qmd` (full-text RSS).
- JSON-LD — `_filters/seo-schema.lua`: `Organization` + `WebSite` + the founder `Person` (`/about.html#founder`, linked as `Organization.founder` and as the `author` of every post) on every page; `BlogPosting` + `BreadcrumbList` on posts; `FAQPage` on `faq.qmd` and on any other page with `.faq-item` blocks (added next to its `WebPage`); `WebPage` (+ `Product`/`Offer` from `schema-offers`) elsewhere; `BreadcrumbList` (Home > sport hub > page) under `nba/`, `wnba/`, `mlb/`. A folder's `index.qmd` is addressed as the folder (`/nba/`), matching Quarto's canonical tag. Set `schema-type: none` in frontmatter to skip a page (the 404 does).
- `og:url`, `og:type` (`article` on posts, `website` elsewhere), `article:published_time`/`modified_time`/`tag` — same filter, from `date`, `date-modified`, `categories`.
- `width`/`height` on body images — same filter, read from the PNG/JPEG file header. An explicit `width=600` on an image is kept and the height is scaled to match. SVGs and remote images are left alone.

Breadcrumbs: pages under `nba/`, `wnba/`, `mlb/`, `stats/` and `guides/` get both a `BreadcrumbList` node and a visible `.breadcrumbs` trail above the body, from the same filter.

The site description is duplicated in three places on purpose (`_quarto.yml`, `SITE_DESC` in the Lua filter, the summary in `llms.txt`); change all three together. Brand facts in the filter's `Organization` node (legal name, founding year, email, `sameAs` profiles) are the canonical entity description — update there first.

## Brand voice
